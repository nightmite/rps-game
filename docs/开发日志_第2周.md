## 二、和 AI 的问答记录（第 3 周报告要用的素材）

### 问题 1：第 1 周用 C++ 写的程序，怎么搬到网页上又不把规则重写一遍？

**我的问法**：这是第 1 周的 C++ 石头剪刀布（贴代码）。请帮我改造成网页版，但不要把赢输规则写乱，
我要能说清楚哪部分对应哪部分。

**AI 的回答要点**：
- 把程序拆成三层，网页版照抄第 1 周的分层：
  `game.h/.cpp`（规则）→ `js/game.js`；`ui.h/.cpp`（界面）→ `js/ui.js` + `style.css`；
  `main.cpp`（流程）→ `js/ui.js` 里的 `playMatch()`。
- 新加的 `js/ai.js` 就是把 `nextComputerMove()` 单独抽出来，方便做难度档位。
- 规则内核不许碰 DOM，这样以后换成别的界面（比如手机 App）也不用改规则。
- 给了对照表：`judge()` → `judge(player, cpu)`，`playRound()` → `playRound(playerMove)`，
  `record.txt` → `localStorage`。

**结果**：`js/game.js` 和第 1 周的 `game.cpp` 逻辑完全对应，自测用的也是同一套判定用例。

### 问题 2：卡片翻牌那个 3D 效果怎么做才不卡？

**AI 的回答要点**：
- 两个面叠在一起，背面用 `backface-visibility: hidden` 藏起来，
  外层给 `perspective: 1000px`，内层 `transform-style: preserve-3d`，
  翻牌就是内层 `rotateY(180deg)`。
- 动画只改 `transform` 和 `opacity`，不要改 `width/height/top/left`，否则每帧都要重新排版。
- 复位（新一局把卡翻回背面）时如果直接移除 class，会看到卡片"倒着翻回去"，
  所以先加一个 `.no-anim` 把 transition 关掉、强制回位，下一帧再恢复过渡。

**结果**：翻牌 0.34 秒，没有掉帧；新一局卡片是"瞬间回到背面"，不会倒放。

### 问题 3：为什么我做出来的动画是"先出结果、后出拳"，感觉很怪？

**我的问法**：我点出拳，比分立刻就变了，然后才播倒数动画，怎么修？

**AI 的回答要点**：
- 结算（`game.playRound()`）要放在动画**之后**调用，比分才会在"揭晓"那一刻跳。
- 顺序建议：亮玩家卡 → 倒数 → 电脑卡抖 → 这时才算分 → 翻电脑卡 → 出结果和特效。
- 用 `await sleep(毫秒)` 把每一步串起来，写成一个 `async` 函数，比一堆 `setTimeout` 嵌套好读。
- 加一个 `busy` 标志，动画没播完时忽略新的点击，避免连点把状态搞乱。

**结果**：现在点下去到出结果约 1.4 秒，节奏刚好；连点也不会乱。

### 问题 4：SVG 手绘手势怎么画才不像一团云？

**我的问法**：我画的三只手看起来像"云朵/团子"，看不出是石头剪刀布，怎么办？

**AI 的回答要点**：
- 不要用一个圆角矩形 + 几个圆拼"整体形状"，那样轮廓会被抹平；
  要画**可辨认的零件**：手掌（圆角矩形）、手指（细长圆角矩形，带轻微旋转）、
  指缝（细线）、袖口（色块），再叠一张小脸。
- 用**两档肤色**（亮面 + 暗面）表现厚度，不要给每个零件加描边——
  描边会画出零件之间互相穿插的线，反而更乱。
- 整个 `<g>` 加 `transform="translate(-15,-15) scale(1.15)"` 把图形放大，
  因为图形只占了 viewBox 的 60%，看起来会小一圈。
- 卡背用粉色、电脑卡用蓝色，左右立刻能分清。

**结果**：重画后，握拳能看到三个指关节、剪刀能看到伸出的两根手指、布能看到五指。

### 问题 5：这台电脑没有 node / npm / playwright，怎么验证网页真的能跑？

**AI 的回答要点**：
- 可以用 Edge 自带的无头模式：`msedge --headless=new --remote-debugging-port=9222`，
  然后用 Chrome DevTools Protocol（CDP）通过 WebSocket 控制它。
- 没有第三方库也没关系：WebSocket 协议自己实现一个最小客户端（握手 + 掩码帧），
  几十行就够。
- 用 `Runtime.evaluate` 在页面里执行 JS（跑自测、点按钮），
  用 `Page.captureScreenshot` 截图，用 `Emulation.setDeviceMetricsOverride` 模拟手机。
- 页面里提前注入一个错误收集器（监听 `error` / `unhandledrejection` / `console.error`），
  最后读出来，就能自动判定"有没有报错"。

**结果**：写了一个 `tools_web/shoot.py`，一条命令就跑完"打开页面 → 自测 → 点按钮 → 截图 → 收集报错"，
最终 0 报错、自测 ALL PASS，还顺手出了 7 张截图。

### 问题 6：不想往网页里塞 mp3，音效怎么办？

**AI 的回答要点**：
- 用 Web Audio 现场合成：`OscillatorNode` 出音高，`GainNode` 控音量和淡出，
  白噪声用 `AudioBuffer` 随机数生成，过一个 `BiquadFilter` 就有"沙沙"感。
- 浏览器要求用户第一次交互后才能出声，所以在第一次点击时 `resume()` 音频上下文。
- 每个音效写成一个函数（赢是上行三音、输是下行两音、结算是小号角），可复用。

**结果**：`js/sound.js` 约 120 行，8 种音效，页面里一个音频文件都没有。

## 四、本周学到的

1. **动画丝滑的关键不是"加更多动画"，而是"只改 transform/opacity + 时长控制"**。
   同一个翻牌效果，改 `width` 会掉帧，改 `transform` 就顺。
2. **顺序就是体验**：先给反馈（玩家卡先翻）、再制造悬念（倒数 + 抖动）、最后揭晓，
   比"点一下立刻出结果"有意思得多。
3. **分层不是形式主义**：规则内核不碰界面，才能第 1 周用 C++、第 2 周用 JS 写两遍还保持一致。
4. **验证比实现更花时间**：为了让截图和自测自动化，我写了 WebSocket 客户端和 CDP 驱动，
   但之后每改一行都能一条命令回归，非常值。
5. **手绘图形要"零件化"**：先想清楚这个物体由哪几个可辨认的部分组成，再去拼，比硬调路径快得多。
